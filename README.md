# 讲义生成

> 一个 macOS 本地 App：把试卷转成备课讲义，点一下，讲义 Word 文档就出来了。
>
> 不用碰命令行，不用另外装东西，打开就能用。

---

## 它是干什么的

老师手里有两份文件：**一份试卷、一份参考答案**，想把它们变成一份能直接用的备课讲义。

这个 App 就是把这件事做完：

1. 你选好试卷和参考答案，点「生成讲义」
2. App 在内置浏览器里登录 DeepSeek，按既定的讲义制作规则，让 AI 写出生成讲义的 Python 脚本
3. App 用自带的 Python 运行这段脚本，产出排版好的讲义 docx
4. 生成完成后，在 Word 卡片里点「下载 Word 讲义」，存到你想放的地方

目标用户就是一位高三英语老师，平时批量把试卷转成备课讲义用。

---

## 基本功能

| 功能 | 说明 |
| --- | --- |
| 上传试卷和答案 | 两个框各放一个 docx：点框选文件，或者直接把文件拖进去；试卷 + 参考答案一起交给 AI |
| 两框查重 | 同一份文件不会同时进两个框（按内容判，复制改名也认得出），防止把答案当试卷传 |
| 按规则生成 | 内置讲义制作规则和标准讲义版式模板，生成结果按这套规则和版式来 |
| 内置 DeepSeek 浏览器 | 不用开 Safari，不用给 Apple 事件授权；登录一次后会话保存在 App 自己的容器里 |
| 浏览器全程隐形 | 生成时浏览器不露面，只有登录时才显示一次，登录成功 5 秒后自动收起；每轮生成前先按 DeepSeek 的 ⌘J 开新对话（本来就停在首页就什么都不做，按不动才回退重载根地址），保证不带上一轮上下文 |
| 自动等、自动续 | 每 3 秒播报一次进度和代码字数；AI 写到一半停了，会自动点「继续生成」续上；整轮等待上限 10 分钟 |
| 模式检测 | 登录后自动检测「深度思考、联网搜索」是否已激活，绿灯亮了才开始检测，5 秒后仍未激活才出现「重新检查」 |
| 下载 Word 讲义 | 生成完成后在 Word 卡片下载 docx，下载成功后临时文件自动清理 |
| 登出 DeepSeek | 标题行末尾的胶囊按钮「登出 DeepSeek」，双绿灯后 0.5 秒出现，生成中禁点；登出时会清掉 cookie 和本地存储，退出后登录行先显示「正在检测」，确认已退出才重新出现登录按钮 |
| 失败只改一行字 | 生成失败时 Word 卡不换按钮、不弹面板，失败原因只改说明行，完整运行日志统一在标题行「详情」里看 |

---

## 用起来是什么样

```text
选试卷 + 参考答案
  → 点「生成讲义」
    → 状态框每 3 秒告诉你：AI 在思考 / 代码目前多少字 / 正在等它继续输出
      → AI 写完，App 自动执行脚本
        → Word 卡片出现「下载 Word 讲义」
          → 点一下，选个地方存下来，就能用了
```

中途不用你盯着点「继续」，也不用你去看脚本、跑命令。

## 界面

- 主背景是实色，不花哨，字看得清
- 上传卡、进度卡、Word 卡和按钮用液态玻璃质感（macOS 26 及以上，低版本自动回退到普通样式）
- 退出确认框：退出在左、取消在右，回车是退出，Esc 是取消；Cmd+Q 不受影响
- 登录状态行是单行固定高度，登录前后窗口不会忽高忽低
- 按钮先保证能点，再谈好不好看：任何 hover 效果都不会挡住点击

## 下载和安装

### 直接下载 Release

到 GitHub Releases 里下载最新版的 `LectureGen-vx.xx.zip`，解压后把「讲义生成.app」拖到「应用程序」里就能用。

用 `curl` 下载还有一个好处：不会被打上隔离属性，也就不会弹 Gatekeeper，装新版前记得先彻底退出旧 App。

### 从源码构建

```bash
cd lecture-app
./build.sh              # 只构建到 dist/讲义生成.app
./build.sh --install    # 构建 + 覆盖安装到 /Applications + 启动
```

没有 Xcode 工程，纯 `swiftc` 手工组装。产物约 77MB，其中约 75MB 是自带的 Python 3.12 + python-docx 运行时，所以用户机器上不用再装 Python。

## 需要注意的几点

- **只支持 macOS**，用的是苹果的 SF Symbol、液态玻璃这些系统专属的东西，换平台要重写。
- **要登录 DeepSeek 网页版**，讲义内容是经由你登录的 DeepSeek 账号生成的；退出账号后会话会被清掉。
- **AI 写完的判定偶尔会误判**，这是这类自动化的通病；失败时先点标题行「详情」看完整运行日志，再重跑一整轮。
- **不要用 JS 点击去点「继续生成」**，DeepSeek 会检查事件是不是真实的，App 里用的是真实鼠标事件注入，这一点别改回 JS 点击。
